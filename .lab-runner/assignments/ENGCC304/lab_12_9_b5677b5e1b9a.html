งานนี้มีจุดประสงค์เพื่อประเมินความเข้าใจจากเนื้อหาที่เรียนมา ผู้เรียนควรสามารถอธิบายแนวคิดและลำดับการทำงานของโค้ดที่ส่งได้

คะแนนถูกแบ่งตาม CLO ของรายวิชานี้คือ CLO1 = 40, CLO2 = 20, CLO3 = 20

1) หลักการตัดสินโดยรวม

  • ระบบเริ่มต้นที่ 100 คะแนน และพิจารณาทั้งความถูกต้องของคำตอบ ความสอดคล้องกับเนื้อหาที่สอน ความซื่อสัตย์ทางวิชาการ และหลักฐานการรันที่จำเป็น
  • การตรวจมีเป้าหมายเพื่อยืนยันว่าโค้ดที่ส่งมานั้นเป็นผลงานที่ผู้เรียนสามารถอธิบายที่มา เหตุผล และลำดับการแก้ปัญหาได้จริง

2) กรณีตัดคะแนนเหลือ 0 ทันที

  • ส่งโค้ดคนละภาษากับที่โจทย์ข้อนี้กำหนด เช่น โจทย์ Java แต่ส่ง #include, scanf, printf, cout หรือ cin หรือโจทย์ C แต่ส่งโครงสร้างแบบ public class, System.out หรือ Scanner
  • ในโจทย์ภาษา C หากใช้รูปแบบ if (scanf(...)) หรือเอา scanf ไปใส่เป็น statement ภายในเงื่อนไข if โดยตรง ระบบจะตีความว่าเป็นรูปแบบที่ผิดเกณฑ์ของรายวิชาและเป็นสัญญาณการพึ่ง AI จึงมีสิทธิ์ตัดคะแนนทันที
  • ใช้ recursion หรือวิธีแก้ปัญหาที่เกินขอบเขตเนื้อหาที่เรียนในช่วงเวลานี้ เช่น ใช้เทคนิคที่ผู้สอนยังไม่สอนเพื่อข้ามสาระหลักที่โจทย์ต้องการวัด
  • ใช้ syntax, library หรือ abstraction ขั้นสูงที่เกินบทเรียนของโจทย์นั้น แม้จะอยู่ในภาษาเดียวกันก็ตาม

3) ความหมายของ “เกินเนื้อหาที่สอน”

  • ระบบจะอิงจากภาษาและแนวทางที่โจทย์ข้อนั้นกำหนดก่อนเสมอ บางข้อเป็นภาษา C บางข้อเป็นภาษา Java จึงไม่ใช้เกณฑ์ของอีกภาษามาตัดสินแบบเหมารวม
  • ถ้าโจทย์ตั้งขึ้นเพื่อวัดความเข้าใจเนื้อหาพื้นฐานที่สอนในภาษานั้น แต่คำตอบใช้เทคนิคที่ล้ำไปมากจนหลีกเลี่ยงสาระการเรียนรู้หลักของโจทย์ ระบบจะถือว่าไม่สอดคล้องกับวัตถุประสงค์ของงาน
  • การใช้ AI เพื่อสร้างคำตอบที่ผู้เรียนอธิบายที่มาไม่ได้ หรือใช้ pattern ที่ผู้เรียนยังไม่เรียนและยังไม่เข้าใจ จะถูกมองว่าไม่ก่อให้เกิดการเรียนรู้ตามที่รายวิชาต้องการ

4) รายการที่หักคะแนนเพราะใช้สิ่งที่ยังไม่สอนหรือเกินขอบเขต

  • คำสั่งหรือ library ที่อยู่นอกขอบเขตของโจทย์นั้น เช่น file I/O, dynamic memory, concurrency, stream/lambda, library เฉพาะทาง หรือ API ขั้นสูงที่ยังไม่สอน
  • syntax หรือ keyword ของอีกภาษา ที่ทำให้คำตอบไม่อยู่ในกรอบของโจทย์
  • คำสั่งหรือโครงสร้างอื่นที่มีผลเทียบเท่าการข้ามไปใช้แนวคิดที่ยังไม่ผ่านการสอนอย่างเป็นทางการ

5) การหักคะแนนด้าน syntax และความถูกต้องของโค้ด

  • ถ้าโจทย์เป็นงานโปรแกรมเต็มและไม่พบ main() ระบบอาจหักคะแนนด้านความสมบูรณ์ของโค้ด แต่โจทย์ที่ตั้งใจให้ส่งเป็นฟังก์ชันจะพิจารณาจากฟังก์ชันตามที่กำหนดได้แม้ไม่มี main()
  • วงเล็บ (), {}, [] ไม่สมดุล หรือมีรูปแบบที่บ่งชี้ชัดว่า syntax ยังผิด
  • string literal ปิดไม่ครบ หรือรูปแบบข้อความไม่สมบูรณ์จนมีผลต่อการคอมไพล์หรือการแสดงผล
  • โค้ดสั้นเกินไปหรือไม่เพียงพอต่อการประเมินว่าได้แก้โจทย์จริงครบตามที่กำหนด

6) หลักฐานประกอบการพิจารณา

  • ไม่มี Program Output: หัก 10 คะแนน เพราะขาดหลักฐานยืนยันผลการรัน
  • ลิงก์ GitHub, Flowchart, YouTube, Debug Sheet และเอกสารแนบอื่น ๆ ไม่ถูกบังคับและไม่ถูกใช้คิดคะแนนในรอบนี้
  • ถ้าส่งผ่าน Lab Runner และ Local Check ผ่านครบทุก testcase ระบบจะถือว่าผ่านด่าน testcase แล้ว แต่ยังตรวจโค้ดที่ submit ต่ออีกชั้นตามเกณฑ์การให้คะแนน การหักคะแนน และความซื่อสัตย์ทางวิชาการ จึงไม่ใช่การการันตี 100/100 อัตโนมัติ

7) การพิจารณาเรื่อง AI และความซื่อสัตย์ทางวิชาการ

  • การใช้ AI เพื่อช่วยคิดคำอธิบายหรือช่วยตรวจ syntax บางส่วนอาจไม่ใช่ประเด็นหลัก หากผู้เรียนยังเป็นผู้ลงมือคิด แก้ และอธิบายวิธีทำได้ด้วยตนเอง
  • แต่ถ้าใช้ AI สร้างคำตอบแทบทั้งหมด แล้วนำมาส่งทั้งก้อนโดยไม่เข้าใจเหตุผลของโค้ด โครงสร้างคำตอบ หรือเทคนิคที่ใช้ ระบบจะถือว่าไม่เป็นไปตามเจตนาของงาน

8) ขอบเขตของการอุทธรณ์หรือโต้แย้งผล

  • หากผู้เรียนต้องการโต้แย้งผล ควรสามารถอธิบายโค้ดของตนได้ทีละส่วน อธิบายเหตุผลที่เลือกโครงสร้างคำสั่งนั้น และเชื่อมโยงกับบทเรียนที่เรียนจริงได้
  • ระบบนี้จึงทำหน้าที่เป็นด่านคัดกรองเบื้องต้นเพื่อส่งสัญญาณชัดเจนว่า การส่งคำตอบที่ไม่ได้สะท้อนการเรียนรู้จริงย่อมมีความเสี่ยงด้านคะแนนอย่างมีนัยสำคัญ
